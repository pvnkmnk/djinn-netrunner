Assessed at master `3a1982e` (PR #253, DJI-501). Every Beta Readiness issue in

plus the DJI-501 resolution. This list is what a GA cut would still want.

## A. Product / behavior gaps

1. ~~**The fallback entrance's identity-gate refusal is test-proven, not
   run-proven.**~~ **ADDRESSED (PR #257, `1603632`):** the e2e stack now serves
   a real but mismatched-tagged FLAC from a documentation-IPv6 sidecar, the
   download passes the guard AND the boundary, and the identity gate refuses
   it live — with a mutation check proving the spec binds to the gate. The
   acceptance record's fallback row carries the evidence.
2. ~~**The allowlist is a beta default, not a GA feature.**~~ **ADDRESSED
   (this PR):** the per-deployment story is documented in BETA_DEPLOYMENT
   (default-deny posture, who edits, restart procedure), and the multi-hop
   public→private post-handover refusal is driven LIVE by
   `e2e/tests/ga-probes.spec.ts` — a public first hop, a 302 to RFC1918 at
   download time, squid `TCP_DENIED/403` on the hop, item terminal, with a
   mutation check (`scripts/mutation-check.sh boundary`) proving the spec
   binds to the boundary. The pre-flight record's honest limit is closed.
3. **The concurrency limit is hardcoded.** The worker runs up to
   `MaxConcurrentJobs = 5` acquisitions at once — a Go constant in
   `cmd/worker/main.go`, not config. The acceptance record's finding 2 asks
   that it "be made explicit"; a GA cut should make it an env setting with a
   documented default (and keep the existing SQLite>1 warning).
4. **`getAlbum` songs report `duration="0"` and an empty `contentType`.** The
   one open client-visible Subsonic polish item, unchanged since first
   recorded. The stream and the file are correct; only the attributes are
   unpopulated.
5. **Cancel semantics leave a partly-acquired release partly acquired** until
   the next sync re-enqueues it. By design, but a GA cut should decide
   deliberately whether re-enqueue is automatic or user-visible.

## C. Test / CI gaps

9. ~~**Mutation proofs for browser behavior are manual procedures.**~~
   **ADDRESSED (this PR):** `scripts/mutation-check.sh` now automates the
   proof — it applies the mutation (gate verdict ignored / `YTDLP_PROXY`
   removed), rebuilds the stack, runs the probe spec expecting FAILURE, then
   restores the snapshot (a copy taken before mutating, not `git checkout`:
   these files carry uncommitted work) and rebuilds clean. Both mutations
   proven live: `gate` → the Soulseek wrong-work spec fails; `boundary` → the
   multi-hop spec fails. Manual proof remains policy for anything without a
   scripted mutation; the decision is written down here.
10. ~~**The boundary is only refusal-tested.**~~ **ADDRESSED (this PR):** the
    success-path probe in `ga-probes.spec.ts` drives a correctly-tagged
    Soulseek download through the fake slskd to import and library
    visibility (job `succeeded`, track in the library) — the Soulseek path's
    own downloads do not traverse the proxy (only yt-dlp egress does), and
    the refusal probes already prove the proxy passes the traffic it should
    (the wrong-work download rides it, `TCP_MISS/200`, before the gate
    refuses). A config mistake that blocks everything fails the fallback
    probes before any gate runs.
